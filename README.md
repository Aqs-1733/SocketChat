# 计算机网络实验三：设计可靠传输协议并编程实现

## 1. 工程与编译

仅保留两个 C++17 源文件：`reliable_udp.cpp`（协议及模拟路由器）、`gui.cpp`（原生 Win32 界面），另附 `build.bat` 和本说明。Windows 网络部分直接使用 Winsock2 基本 Socket 函数，无 Socket 封装类或第三方网络框架。Linux 分支用于独立验证协议逻辑。

打开 Visual Studio 的 x64 Native Tools Command Prompt for VS，进入本目录：

```bat
build.bat
```

生成 `reliable_udp.exe` 和 `reliable_udp_gui.exe`，两者放在同一目录。双击 GUI 程序即可演示；本源码包未预置未经 Windows 验证的 EXE。

## 2. 图形界面操作

1. 浏览并选择源文件，设置接收文件路径。源文件和目标文件不能相同；已有目标文件需要确认覆盖。
2. 设置收发窗口（1~4096 包）、随机丢包率（0~99%）、单向时延（0~10000ms）、报文误码率（0~99%）、重传超时（100~60000ms）和路由端口（1024~65534）。双方窗口相同；接收端端口为路由端口加一。报文误码率表示未被丢弃的 DATA 报文中被翻转一位的概率，不是逐比特误码率。
3. 点击开始传输。若超时不大于模拟 RTT 加20ms，GUI 将明确提示并调整为两倍单向时延加100ms。传输中锁定参数。
4. 查看真实收发日志、两个窗口边界、乱序缓存数量、连续确认进度、重传次数、RTT、耗时及平均有效吞吐率。接收端校验并保存文件，双方进程正常结束后界面才显示成功。
5. 每次实验的完整日志自动保存到接收目录下的 `transfer_进程号_时间标识.log`。清空界面日志不影响文件日志。结束后可以点击保存日志另存。
6. 停止或失败不会把未完成文件覆盖到目标文件上。接收端使用 `.part.进程号` 临时文件，正常异常退出由接收端清理，GUI 主动终止子进程后尝试清理本次临时文件。若整个程序遭到系统强制终止或断电，可能留下临时文件，可手动删除。

GUI 通过匿名管道读取三个独立进程的实际日志；三个进程确实通过 UDP 回环接口通信。命令行模式也支持跨主机 IPv4 通信。日志按各子进程输出顺序读取，三端合并后的排列不代表精确的跨进程时间顺序。

## 3. 协议设计

### 报文格式（RTP2）

所有整数采用网络字节序。首部固定32字节，每个 DATA 最大载荷1200字节。新旧协议格式不兼容，必须同时替换两端及路由程序。

| 偏移 | 字节数 | 字段 | 含义 |
|---|---:|---|---|
| 0 | 4 | magic | 0x52545032，RTP2 |
| 4 | 4 | session | 会话标识 |
| 8 | 4 | type | 报文类型 |
| 12 | 4 | seq | DATA/ACK的包序号；SYN/FIN的全文件校验值 |
| 16 | 4 | length | 载荷长度 |
| 20 | 4 | checksum | 高16位置零，低16位为反码和校验值 |
| 24 | 8 | info | SYN/FIN为文件字节数，SYN_ACK为窗口大小 |
| 32 | 0~1200 | data | DATA载荷；SYN含两个32位参数（窗口、重传超时） |

类型编号：SYN=1、SYN_ACK=2、DATA=3、ACK=4、FIN=5、FIN_ACK=6、BAD=7、OPEN_ACK=8、CLOSE_ACK=9、RESET=10。

### 连接管理

发送端发送SYN，接收端检查文件长度及窗口、超时参数，窗口不一致返回RESET。接收端回复SYN_ACK，发送端回复OPEN_ACK；首个合法DATA或FIN也能确认连接，处理OPEN_ACK丢失。接收端只接受同一通信对端、同一会话的报文。

全部DATA得到确认后，发送端发送FIN。接收端检查字节数和完整文件校验值，检查文件关闭写入状态，再将临时文件保存为目标文件，回复FIN_ACK。重复FIN会再次获得FIN_ACK。发送端收到FIN_ACK后发送三份CLOSE_ACK，降低最后确认丢失的概率。接收端收到任一CLOSE_ACK后退出；若全部丢失则保留会话到有限等待期结束。双方成功的判断分别基于收到FIN_ACK、文件通过验证；有限次报文交换不能在任意永久丢包条件下保证双方都收到最后确认。

建连、数据报文和关闭请求最多发送30次（含首次发送），失败返回非零退出码。接收端初始等待至少60秒，连接后的无活动超时和关闭等待期取 max(10000ms, 32×发送端RTO)。连接后的本地错误尽量发送RESET通知对端；即使RESET丢失，对端仍有超时退出机制。

### 差错检测

对首部和载荷进行16位二进制反码求和，最高位进位回卷，奇数字节末尾补零，发送端取反后写入校验字段；接收端计算包含校验字段的反码和，取反结果为0才接受。报文类型、长度也需要合法。FNV-1a仅用于完整文件的额外校验，不替代报文校验和，也不是密码学哈希。验收建议再使用 `fc /b` 或 SHA-256 对比文件。

### 确认重传及窗口

发送窗口为 `[base, base+window)`，`next` 表示下一个未发送包。`pending` 仅保存已发送但尚未确认的数据、发送时间和发送次数。收到独立ACK后删除对应条目；`base` 跳过已经确认的连续序号。对仍在 `pending` 中且超时的报文逐个重传，不重发已确认包。无需按文件总包数分配确认数组。

接收窗口为 `[base, base+window)`，窗口内报文按序号缓存并独立确认，连续数据按序写入文件。已交付的重复报文再次ACK但不写入文件，窗口右侧以外的报文丢弃。两端窗口固定且在建连阶段检查一致性。

### 模拟路由器及统计

路由器按方向转发原始UDP载荷，在转发前随机丢弃报文、按配置延迟进入FIFO队列，或翻转DATA首个载荷字节的一位，故意保留原校验和。丢包对数据和控制报文均有效。固定延迟不主动制造额外乱序，但丢包后重传使后续包先到达，足以验证SR的乱序缓存功能。

发送端总耗时从首次SYN前开始，到关闭确认完成为止，不含预先读取文件计算全文件校验值的时间。平均有效吞吐率为文件字节数×8÷耗时÷10^6（Mbps），不含重传流量。RTT只统计首次发送就获得ACK的样本，避免重传产生歧义；无有效样本显示N/A。GUI统计会受本机日志和调度开销影响，性能比较需要保持实验环境一致。

## 4. 命令行运行及专项验证

在三个终端中依次运行，`test.bin` 换成实际文件：

```bat
reliable_udp.exe recv received.bin 9001 16 500
reliable_udp.exe route 9000 127.0.0.1 9001 20 40 5
reliable_udp.exe send test.bin 127.0.0.1 9000 16 500
```

路由参数依次为监听端口、接收端IP、接收端端口、丢包率、单向时延、报文误码率（可省略，默认0）。路由器每次实验重新启动。命令行模式的RTO需要手动设置得大于预期RTT。若无需模拟路由器，发送端直接连接接收端9001端口即可。

为方便复现控制报文丢失或误码，在路由参数末尾附加一个故障名称。例如：

```bat
reliable_udp.exe route 9000 127.0.0.1 9001 0 10 0 DATA
reliable_udp.exe route 9000 127.0.0.1 9001 0 10 0 FIN_ACK
reliable_udp.exe route 9000 127.0.0.1 9001 0 10 0 CORRUPT
```

每次仅执行其中一个路由命令，并重新启动收发端。可选故障包括 `SYN`、`SYN_ACK`、`OPEN_ACK`、`DATA`、`ACK`、`FIN`、`FIN_ACK`、`CLOSE_ACK`（对应类型的首个报文丢弃），`CORRUPT`（首个未丢弃DATA翻转一位）。随机丢包和随机误码均设0可单独验证指定故障。关键日志：`[SYN]`、`[SYN_ACK]`、`[OPEN_ACK]`、`[CONNECTED]`、`[SEND]`、`[RECV]`、`[ACK]`、`[RETX]`、`[WINDOW]`、`[RECV_WINDOW]`、`[DUPLICATE]`、`[DROP]`、`[CORRUPT]`、`[CHECKSUM_ERROR]`、`[FIN]`、`[FIN_ACK]`、`[CLOSE_ACK]`、`[CLOSED]`、`[RESULT]`、`[ERROR]`。

验证文件内容：

```bat
fc /b test.bin received.bin
certutil -hashfile test.bin SHA256
certutil -hashfile received.bin SHA256
```

Wireshark 回环接口显示过滤器：`udp.port == 9000 || udp.port == 9001`。自定义首部需结合上述偏移解释。

## 5. 本版实际验证记录

Linux/GCC，`-std=c++17 -Wall -Wextra -Wpedantic -O2`，后端编译通过。以下为本版实际测试，不是 Windows 或教师指定文件的测试结果：

- 校验和：已知奇数字节样例 `01 02 03` 的校验值为 `0xfbfd`；35字节完整报文逐位翻转共280次，全部被拒绝。
- 21组端到端测试全部通过，收发两端均退出0，文件逐字节一致，无残留临时文件。包括空文件、单字节、2400字节整块、24001字节非整块、中文和空格文件路径、25%及35%丢包、20%报文误码、8类报文分别单次丢失、定向误码、1/4/16/64/256包窗口。定向DATA丢失出现后续包缓存与对应序号重传；ACK丢失出现重复DATA；定向误码出现校验错误与重传。
