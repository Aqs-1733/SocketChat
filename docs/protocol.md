# SimpleChat/1.0 聊天协议说明

## 1. 基本约定

协议运行于 TCP（IPv4 + `SOCK_STREAM`，默认服务器端口 8888），采用 C/S 模型。TCP 自身没有应用消息边界，因此在每条应用层协议报文结尾放置一个 `LF`（字节 `0A`），接收端逐字节积累并寻找 LF；允许 `CRLF`（`0D 0A`）。一条消息最多 8192 字节（不含行结束符）。终端用户输入只能是一行文本。

全部应用层文本字段采用 UTF-8；不接受无效 UTF-8。正文可以包含字符 `|`，所以 `TEXT` 只对前两个 `|` 分割，`MSG` 只对前四个 `|` 分割。用户名不含 `|`。正文不允许换行、回车、NUL 和其他 ASCII 控制字符（制表符除外），长度 1～4096 UTF-8 **字节**。

## 2. 消息语法与语义

| 方向 | 语法（末尾均附 `\n`） | 语义 |
|---|---|---|
| C→S | `JOIN|name` | 请求登录；name 为 1~16 位 ASCII 字母/数字/下划线，区分大小写 |
| S→C | `WELCOME|name|YYYY-MM-DD HH:MM:SS` | 登录成功，确认用户名和服务器本地时间 |
| C→S | `TEXT|seq|content` | seq 从 1 开始严格逐次递增；content 是聊天内容 |
| S→全部在线用户 | `MSG|time|name|seq|content` | 服务器在收到 TEXT 时生成 time，再向所有在线用户广播（包括发送者） |
| C→S | `WHO` | 查询当前在线用户名 |
| S→C | `USERS|name1,name2,...` | 当前在线用户列表，按用户名字典序排列 |
| S→全部在线用户 | `NOTICE|time|text` | 用户加入、退出的系统通知 |
| S→C | `ERR|code|reason` | 表示请求不能执行，具体原因见下表 |
| C→S | `QUIT` | 用户主动退出 |
| S→C | `BYE|time` | 服务器确认退出 |

`time` 固定格式为 `YYYY-MM-DD HH:MM:SS`，时区采用**服务器所在操作系统的本地时区**，精度为秒。此时间不是 IP 数据包的时间戳或 TCP 报文发送时间。`seq` 为客户端生成的无符号 64 位正整数，客户端各自从 1 开始；不是 TCP SEQ。每条会话的 seq 严格连续，非法或被拒的消息不消耗序号。

### 错误代码

| 错误码 | 处理规则 |
|---|---|
| `BAD_NAME` | 用户名无效；保留连接，可重新 JOIN |
| `DUP_NAME` | 用户名已被其他会话使用；保留连接 |
| `ALREADY_JOINED` | 已登录后再次 JOIN；保留连接 |
| `FULL` | 最多 32 个在线用户；保留连接 |
| `NOT_JOINED` | 登录前发送其他请求；保留连接 |
| `BAD_FORMAT` | 未知命令/字段不匹配；保留连接 |
| `BAD_SEQ` | 消息序号缺失、非法或非期望的下一个整数；保留连接 |
| `BAD_UTF8` | 整条协议帧包含无效 UTF-8；保留连接 |
| `BAD_TEXT` | 正文为空/控制字符/非法 UTF-8；保留连接 |
| `TOO_LONG` | 正文超过 4096 字节则保留连接；单帧超过 8192 字节则发送错误并关闭连接 |
| `BUSY` | 未登录连接已达 64 个；拒绝新连接 |

如果 TCP 对端无通知地关闭连接，服务器通过 `recv()==0` 或 Socket 错误感知断开，移除在线用户并发送 NOTICE。

## 3. 交互举例

客户端 A：`JOIN|Alice\n`  
服务端 A：`WELCOME|Alice|2026-10-14 15:30:00\n`  
客户端 B：`JOIN|Bob\n`  
服务端 B：`WELCOME|Bob|2026-10-14 15:30:02\n`  
客户端 A：`TEXT|1|你好 Bob!\n`  
服务器向 A、B 广播：`MSG|2026-10-14 15:30:05|Alice|1|你好 Bob!\n`。

**以上时间仅是协议语法示例，不是实验实际测量数据。**

## 4. 时序约束

1. 客户端先发起 TCP 连接，然后在应用层发送 JOIN。
2. 服务端检查昵称有效、未重复、容量未满后将用户加入在线列表，发送 WELCOME，广播上线 NOTICE。
3. 已登录客户端可以发送 TEXT、WHO、QUIT；收到 TEXT 后服务器校验序号/正文，再使用服务器本地时间戳生成 MSG，向当前在线用户广播。
4. 正常退出时客户端发送 QUIT；服务端发送 BYE、清理用户记录，通知其他用户。
5. 客户端突然断开时服务器对剩余用户发 NOTICE；断线用户重新连接需要重新 JOIN，应用序号重新从 1 开始。

## 5. 关于 TCP 的重要区别

多次 `send()` 的数据可能由一次 `recv()` 读到；一次 `send()` 的数据也可能需要多次 `recv()` 才完整。UTF-8 汉字字节也可能跨越接收块。因此应用层缓冲区不能按照 `recv()` 调用次数决定聊天消息数量，而要寻找 LF 并对每个完整帧独立解析。

程序的 `send_all()` 只保证本次 Socket 调用已经接受全部待发送字节，不能直接等同于远端应用成功显示消息。测试阶段必须检查每个客户端的 `MSG` 序号与内容。
